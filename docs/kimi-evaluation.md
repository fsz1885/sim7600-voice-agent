# Kimi 真实调用与延迟实测

模型 ID：`kimi-for-coding`、`kimi-for-coding-highspeed`；
接口：`https://api.kimi.com/coding/v1`。
使用用户提供的 Kimi Code 密钥，密钥仅存在于被忽略的本地 `.env`。
真实评测在 Windows 宿主机 Python 3.12 环境运行；Docker 另外执行离线回归测试。

每轮计时从 `Agent.handle_turn` 开始，到完整 Decision 返回结束，含 HTTP、全量 JSON 生成、
本地校验和可能的重试。非流式，不测首 token、不含用户输入时间或 ASR/TTS。
每个 HTTP 调用新建客户端，因此包含连接建立开销；未测持久连接。

## 普通版历史测试

共进行三次会话、27 次真实 chat/completions 请求，27 次均成功返回，没有修复重试。
三次之间修改过提示词/输入格式，不能作为同一版本的稳定性统计。

| 轮次 | 平均秒/决策 | 中位数 | 最慢 | 收集完成 | 观察 |
| --- | ---: | ---: | ---: | --- | --- |
| 初测 | 5.817 | 5.592 | 7.484 | 9/9 字段 | 有跨字段连问，值丢失前提条件 |
| 强化单问题及条件保留 | 6.361 | 4.699 | 15.251 | 8/9 字段 | 漏提取最后一轮注册周期，模拟回答用尽后停止 |
| 明确标注最新回复、精简重复状态（最终版本） | 6.384 | 6.635 | 8.593 | 9/9 字段 | 保留了条件，能澄清并结束；仍有额外追问 |

最后一轮：9 次调用，最低 4.570 秒，最高 8.593 秒，小样本最近秩 P95 为 8.593 秒。
9 个样本的 P95 实际就是最大值，不能作为服务长期 P95 承诺。

最终结果正确保留“地址本身免费，但是必须在我们这里做代理记账”和
“材料齐全后5到7个工作日”；价格从 partial 转为 confirmed（每年2400元人民币）。

仍存在的语义问题：澄清价格时模型问了“是按月算还是按年算？另外包含哪些服务？”。
虽围绕价格，但仍包含额外问题，未严格达到每轮只问一个核心问题的要求。
Core 的 target_field 检查只能约束结构，不能保证自然语言句子完全遵守行为规范。
本次完成状态不等于所有对话质量指标均通过，仍需要独立语义评测与进一步约束。

延迟判断：目前完整文本决策通常需要约 5–8 秒，曾出现 15 秒长尾；
对自然电话交互偏慢。高速版追加实测见下文；连接复用及更精简的状态仍待验证。

最终代码的本地及 Docker 自动化回归：51 项测试通过，Ruff 通过，Docker 构建通过。
这些回归仍然全部离线，真实 LLM 评测是显式单独运行的步骤。

## K2.7 Code HighSpeed 追加测试

按用户指定，请求模型 ID 为 `kimi-for-coding-highspeed`。
测试沿用代码版本 `341341465b14e1d7dd5366114dae127ae25bdb83`、相同提示词、任务、
模拟对方回答、非流式请求和关闭 thinking 的配置，仅在评测进程中覆盖 `LLM_MODEL`。
本地 `.env` 的默认模型没有改变。模型由 API ID 指定，未独立确认服务端实际模型版本。

本次为一段完整会话，9 次真实请求全部成功，没有修复重试。
连同上方普通版历史测试，累计 4 段会话、36 次真实请求。

| 指标 | 普通版最后一次测试 | HighSpeed 本次测试 |
| --- | ---: | ---: |
| API 调用次数 | 9 | 9 |
| 成功 HTTP 请求 | 9 | 9 |
| 修复重试 | 0 | 0 |
| 平均完整决策耗时 | 6.384 秒 | **9.944 秒** |
| 中位数 | 6.635 秒 | **7.798 秒** |
| 最快 | 4.570 秒 | 3.402 秒 |
| 最慢／小样本最近秩 P95 | 8.593 秒 | **21.593 秒** |
| 已确认字段 | 9/9 | 9/9 |
| 含糊价格澄清 | 是 | 是 |
| 最终完成 | 是 | 是 |

HighSpeed 逐轮耗时（秒）：
`3.402, 6.624, 8.617, 5.691, 7.798, 8.094, 6.399, 21.593, 21.280`。
最后两轮分别为处理材料并询问周期、处理周期并结束会话，均超过 21 秒；
API 调用记录没有重试，因此这两个长尾不是 Core 修复重试造成的。

本次平均耗时比历史普通版样本高约 **55.8%**，没有观察到完整决策加速。
两组测试并非同时交错运行，网络、服务负载和生成内容存在差异，且每组只有 9 个样本；
不能据此断言高速版长期更慢，也不能将该结果视作输出 tokens/s 或首 token 延迟对比。
没有记录首 token、生成 token 数或服务端排队时间，目前不能进一步定位慢在何处。

对话质量检查：

- 正确从一条回答更新地址费用、强制绑定记账和是否实际办公三个字段。
- 价格由 partial 转为 confirmed，并保留每年2400元人民币。
- 保留地址免费的记账绑定条件、银行审核限制及“材料齐全后”的周期前提。
- 未重复询问已 confirmed 的字段，最终自然结束。
- 仍有多问题现象：“两千多是包年的价格吗？包含哪些服务？”。
- “材料收到”措辞不够准确：模拟对方只是说明所需材料，并没有真正交付材料。

结论：本次任务收集完成，但延迟和口语规范尚未达到目标；不建议仅凭 HighSpeed 名称
就替换默认模型。下一步应在同一时段交错多次测试，补充首 token 和输出长度记录后再判断。
本次仅新增评测记录及文档，没有修改运行代码，未重复执行离线回归。
