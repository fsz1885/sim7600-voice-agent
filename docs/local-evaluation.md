## 本地模型选择与实际结果

默认选用 `qwen3.5:4b`，Ollama manifest digest：
`2a654d98e6fba55d452b7043684e9b57a947e393bbffa62485a7aac05ee4eefd`。
官方打包约 3.4 GB、Q4_K_M；调用仅文本、`think=false`、8192 上下文、单并发。
`/api/ps` 报告 `size=size_vram=3341958511` 字节（约 3.11 GiB），无 CPU 权重卸载。
当时整卡使用约 5195 MiB，包含桌面和其他进程，不能全部归因于模型。
发布信息见 [Ollama 模型页](https://ollama.com/library/qwen3.5:4b)。

五类场景使用固定书写输入，不是独立盲测集；每类先生成开场，再输入一到两条回答。
最终检查要求字段状态/值/证据符合指定断言，并且整个场景没有 retry/handoff。
断言仍是有限检查，不能把通过率解释为通用语义准确率。

| 场景 | 最终结果 | 观察 |
| --- | --- | --- |
| 不确定费用 | 通过 | partial 并追问，不错误确认 |
| 金额更正 | 通过 | 每年三千元改为每年两千五百元，保留两轮证据 |
| 否定 + 未知材料 | 通过 | 无需实际办公被记录，材料未错误确认 |
| 免费地址附带记账绑定条件 | **未通过** | 费用保留绑定条件，但“必须购买”仍被标成 partial，重复追问 |
| 明确不适用 | 通过 | 明确不提供服务且费用不适用，正常完成 |

[最终原始数据](local-evaluation-4060-final.json)：4/5 场景通过、11 次成功 HTTP 调用，
完整决策中位数 2.596 秒、最大 4.082 秒。本轮 LLM 已加载，不能称为冷启动延迟；
此前 Qwen3.5 冷模型首轮为 30.847 秒（含加载及首次预填充）。
样本太少，不报告 P95/P99，不承诺达到历史方案中的亚秒级目标。
模型仍会进行不必要的再次确认；本轮未修改 Core 或强行将 partial 提升为 confirmed。

## 语音与服务链路

SenseVoice INT8（`language=zh, use_itn=True`）、Matcha 3 steps + Vocos，CPU 各 2 线程。
归档 SHA-256 与仓库已有 comparison-manifest.json 完全一致。
在正式 ASR 前增加能量门限：明显静音被拒绝；不声称可以可靠过滤所有噪声。

最终回环的两句结果：

- “您好，请问注册地址的费用是多少？”转写一致；首次 TTS 1.948 秒、ASR 1.327 秒，含各自加载。
- “不是三千元，是每年两千五百元，不包含刻章费用。”转写为
  “不是3000元，是每年2500元，不包含客章费用。”；TTS 0.320 秒、ASR 0.230 秒。

第二句存在“刻章→客章”错误，不能仅凭数字和否定保留就认为语音完全正确。
Matcha 加载时仍报告历史已见的 `shei2` 词典警告；没有人工听辨音质。

[实际控制台 HTTP 回环](local-console-smoke.json) 使用真实本地 LLM、ASR/TTS，
完成三轮输入：含糊费用 → 明确费用和材料 → 明确材料清单没有其他项，最终 finish。
校验了静态页面资源响应、全部音频 WAV 可读取、阶段事件和最终字段证据。
[两轮初次结果](local-console-smoke-initial.json) 未完成，因为模型仍追问材料完整性；
第三轮是显式补充回答，并非自动伪造确认。

**所有音频来自 TTS 合成，未测试真人麦克风、实际扬声器听感、真实电话、SIM7600、
运营商线路、浏览器交互自动化或完整端到端延迟。** 浏览器权限和自动播放仍需在实际使用时验证。
当前交付是可运行的本机分轮语音控制台，适合开发验证，不是已验收的生产电话系统。
